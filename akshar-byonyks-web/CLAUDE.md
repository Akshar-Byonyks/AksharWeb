# Akshar Byonyks website — standing rules

Full spec: `../docs/aksharbyonykswebsitespec.md` (currently v0.7). Read it before making architectural decisions this file doesn't cover.

- **Consult Context7** before writing Next.js App Router, OpenNext, Keystatic, next-intl, Pagefind or Turnstile code. All of these move fast — do not write framework code from memory.
- Run **`/impeccable audit`** on every new template before it goes to review.
- **Server Components by default,** the App Router's default rendering mode. See spec 12.9 for the client-component reference list — it's not a gate to clear (v0.7).
- No first-load-JS measurement is required before merging during frontend build (spec 11.3, deferred). That changes at the post-frontend performance pass.
- Every colour must resolve through a token from spec Section 6.1 (`--primary`, `--background`, `--foreground`, etc. in `src/app/globals.css`). **No hardcoded hex and no arbitrary Tailwind colour values in components.**
- **Reach for a real image first** (client direction, 28 Aug 2026). Every page-level template and every section big enough to carry one should be actively considered for photography before it ships as type and line art. Go and look for a picture rather than defaulting to a glyph — Byonyks USA's own asset library first, then rights-cleared stock (Pexels and Unsplash are free for commercial use; Wikimedia Commons needs attribution). Prefer **India-specific** imagery over generic: a photograph that could be anywhere is worth less here than no photograph. Authored line art is now the fallback for subjects that genuinely cannot be photographed, not the resting state. Full doctrine in `DESIGN.md`, "Imagery".
- **Three hard gates on any image, no exceptions.** (1) **Download it and look at it** before using it — two of the first five candidates were rejected on sight and neither could have been rejected from its filename. (2) **Record provenance in `public/images/README.md`** — source URL, licence, fetch date, and every edit made. (3) **Text over an image uses `ScrimmedImage`**, which has the scrim built in with no prop to disable it (spec §7.2; §2 names unscrimmed hero text as the most common AA failure on marketing sites).
- **Images of people in a clinical or therapy context are a legal question, not a design one.** India's Drugs and Magic Remedies (Objectionable Advertisements) Act 1954 constrains them. The client has approved this category as of 28 Aug 2026, so use it — but flag every instance in `public/images/README.md` for legal sign-off before launch (spec §14.4). Never caption a render as a photograph.
- Prefer **shadcn primitives** over hand-rolled interactive controls, and the **native element** over both where it does the job.
- **State how a fact is known, using the provenance scale** (30 Aug 2026). Four statuses on the four existing accent roles — `record` (plum, a public register), `published` (teal, research), `stated` (primary, a company statement), `pending` (amber, not established). Use `ProvenanceMark` in the document spine's gutter, or `ProvenanceChip` in a table cell. **The scale no longer attributes anything to Byonyks by name** (2 Sep 2026): the client holds Byonyks' permission for its material and asked for the source citations and the attributions to come off, so `stated` reads "Company statement", `statedBy` is optional and the Byonyks-sourced entries omit it. What the status still carries is the part that was never about permission — that the claim is unverified from here — and the `pending` chip beside it still names the specific number that is missing. **Do not reintroduce a byonyks.com source line or a retrieval date into a rendered mark.** FDA, research and news citations are untouched and must stay. **Gold is not in this scale** and must not be added to it. A new claim also gets an entry in `src/lib/claims-ledger.ts`, which backs `/what-we-know/`.
- **Prose sections use the document spine** (`components/layout/document-grid.tsx`), not a left-pinned `max-w-3xl`. A section is **railed or wide, including its heading** — never a mix, or the page grows a third left edge. If a block has nothing to put in the gutter it is `wide`, not railed. The five legal documents keep their own centred shell: their index is navigation, not annotation.
- **A number set large uses `DisplayFigure`**, not a hand-rolled `text-5xl font-bold`. Four steps, tabular figures always. Every use carries a source, a date or a status on the same row — otherwise it is the hero-metric template the craft floor refuses.
- **The Hindi track is `/hi` only, and there is no `[locale]` segment.** Do not restructure `src/app` for locales. Add Hindi strings to **both** `messages/en.json` and `messages/hi.json` — the module-load check in `src/i18n/messages.ts` fails the build if the keys drift, because next-intl renders a missing key as the key path rather than erroring. Never `font-mono` or `tracking-*` on Devanagari; `globals.css` handles the rest under `[lang|="hi"]`. **Hindi copy is unreviewed and every Hindi page says so** — do not remove that notice without a qualified medical translator's sign-off.
- **An accent's meaning gets carried by `AccentRail`, not by a new tint** (30 Aug 2026). Gold "home/India", teal "clinical evidence", plum "institutional/formal", primary the regulatory workhorse — a 1px rule beside the content, `aria-hidden`, and never the only place a distinction appears. It answers *what kind of thing this is*; `ProvenanceMark` answers *how a fact is known*. Do not spend an accent on a control: play buttons and links are neutral or primary, always. Before adding a rail, check the meaning is already there — a section with no accent is correct far more often than a section with a decorative one, and `/innovation`'s doorways, `about-hero` and the five legal documents refuse accents on purpose.
- **Anything that gates the page must fail open without React** (30 Aug 2026). The opening curtain on Home (`components/motion/site-splash.tsx`) is server-rendered markup raised by an injected stylesheet, so the timeout that lifts it cannot live only in a `useEffect` — block a chunk, hydration dies, and the visitor is sealed out of a medical-device site by a decoration. The inline script in `layout.tsx` that arms it also schedules its own removal (`SPLASH_FAILSAFE_MS`). **Keep both ceilings, and do not raise either** — the client removed the Skip button and the once-per-session gate (30 Aug 2026), so the timers are now the only exit from an unskippable curtain that fires on every load of Home. If it needs to feel shorter, lower `SPLASH_MAX_MS`. The curtain stays Home-only, holds nothing focusable, `inert`-guards everything behind it, and never appears without JavaScript — do not widen any of that.
- **One family, Noto Sans, and there is no longer an exception** (1 Sep 2026). Spec Section 6 fixes Noto Sans for every display and text role, and nothing on this site now sits outside it. A `Yellowtail` declaration stood in `layout.tsx` for a few hours that day so the opening curtain could answer "change font on loading animation to Byonyks logo font"; it is gone, along with `SPLASH_FONT_METRICS`. **The curtain sets no type at all** — it draws outlines from `src/lib/splash-wordmark.ts`, so it loads no webfont, cannot show a fallback face and then jump, and is identical on the server and in the first paint. Do not reintroduce a display face for it: the answer to "make the wordmark look like X" is to generate outlines from X, and the recipe is in `public/images/README.md`.
- **A logo is artwork before it is a typeface, and a lookalike font is the second-best answer** (1 Sep 2026). The curtain's wordmark was matched to a face three times in one day — Pacifico against the Byonyks mark, Yellowtail against the Akshar Byonyks lockup, and then neither, because the client sent the Byonyks mark and asked if the curtain could look like *that*. It could not, with any font: **the B is drawn, with a flourish above it and a tail that sweeps under the whole word, and no typeface contains it.** When a brand mark carries custom lettering, stop hunting for the face and trace the artwork. When a face genuinely is the answer, still render the candidates directly underneath a crop of the real logo and look — that is how Pacifico was picked for "Akshar", and how Yellowtail was caught being wrong.
- **The brand assets are derived from one supplied file, and the crops are recorded.** The nav emblem (`public/images/brand/`), the share card (`src/app/opengraph-image.jpg`) and the favicon (`src/app/icon.png`) are all cut from the client's `Akshar Byonyks Logo.png`. The full lockup is a near-square stacking a globe, a monogram, a script wordmark, an entity line and a two-line tagline — **it is unusable below about 200px wide**, which is why the nav gets the emblem alone and the share card gets the lockup. Crop boxes and reasoning are in `public/images/README.md`. **The nav emblem now has a transparent background** (2 Sep 2026), so the ink footer is no longer blocked from carrying a logo. A threshold knockout does punch holes through this mark — the continents are silver and the keyline round the monogram is white — and so does a single border flood fill loose enough to catch the antialiased edge, which squeezes through the specular on the globe's rim. **Knock out background by flood-filling at a threshold too strict to squeeze a rim, then dilate and grade the edge inside that dilation**; the measured thresholds are in the README. Do not re-derive this by thresholding.
- **A page's Open Graph image must be on that page's own `openGraph`, via `defaultOg` from `src/lib/seo.ts`** (1 Sep 2026). Next merges route metadata *shallowly per top-level key*, so a page exporting any `openGraph` object replaces the parent's entirely — declaring `images` on the root layout reaches Home and nothing else, and so does the `opengraph-image` file convention on its own. Both were measured. **Any new page with an `openGraph` block needs `images: defaultOg`** unless it has real imagery of its own.
- **React Bits components are ported, adapted and token-mapped — never dropped in.** Licence is MIT + Commons Clause: using them inside this site is granted, redistributing them (including as a port) is not. Their colours are hardcoded hex and must move onto tokens; `var()` does **not** resolve in SVG presentation attributes (`stroke=`, `fill=`), so pass paint through `style`. Do not add gsap — `futureIdeas.md` rejected a component over that dependency once already, and both animations `StrokeText` needed turned out to be plain CSS.
